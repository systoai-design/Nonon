## Division of labour (what is code, what is the model)
| Step | Who | Notes |
|---|---|---|
| Read CSV / XLSX, header row, amounts, dates, sheet choice | code | papaparse, exceljs, jszip. Source row numbers kept as shown in Excel. |
| Column mapping | code, model may suggest | Header names AND value shapes. Model hints are used only where code is unsure, only if the named column exists and the values fit. The user still confirms through a question with a `suggested` answer. |
| Matching, duplicates, ambiguity, totals | code | Integer cents only. Reference first, then amount + date window + wording, one-to-one, ties are `ambiguous`. |
| Output workbook, reopen-and-validate | code | Values only, no formulas. |
| Explanation | model (one call, retry once) | zod-validated JSON; every figure and every `row N` must appear in the facts it was given, else retry then a labelled standard summary. |
| Staged change to file A | code | `csv-set-cells` / `xlsx-set-cells` with `appendColumns`; nothing written to originals. |

## Conventions the other workstreams should know
- **Proposal row alignment**: `appendColumns[k].values[i]` belongs to the row after the header, `i = 0` is file row 2. Verified against `changes/csv.ts` and `changes/xlsx.ts` by `apply-seam.test.ts`. A proposal is only offered when the header is on row 1 and (for xlsx) the workbook has no macros, charts, pivots, links or embedded objects; otherwise a `proposal-offered` warn check says why and the comparison workbook still has everything.
- **Preview**: `before` and `after` are string tables whose first row is the header and whose first column is the original row number. `highlights` index into `after`: row 0 is the header, the last two columns are the new ones. Up to 12 data rows, rows that need attention first.
- **Question ids**: `sheet.a|b`, `map.a|b.{date,description,reference,amount,debit,credit}` (value is the header text, `__none__` for optional fields), `rule.dateOrder.a|b` (`DMY` or `MDY`), `rule.amountSign` (`opposite`, `ignore`, `same`; honoured only when the files really use opposite sign conventions), `rule.period` (`overlap`, `all`), `rule.amountTolerance` (text, `0.00`), `rule.dateToleranceDays` (text, `3`). Remembered answers that do not match the current files are ignored and the question is asked again.
- **Report shape** (`ProcedureOutcome.done.report`): `{kind, revision, files, mapping, rules, counts, totalsCents{a,b,difference,byClass[]}, top[10], explanation{source, summary, checkFirst, attempts, timingMs}}`.
- **Checks** emitted: `files-read`, `formula-no-result`, `unsupported-features`, `header-not-first`, `skipped-rows-a|b`, `unreadable-dates-*`, `no-description`, `account-for-every-record`, `difference-explained`, `weak-matches`, `output-reopened`, `ai-explanation` (warn, only on fallback), `proposal-offered`.

## Honest limits and open risks
- Matching is a reviewing aid. Rows that fit more than one partner equally well are listed as unclear, never guessed; a pair matched only on amount and date is flagged.
- Day/month order is proven from the data when possible; otherwise it is asked, with a suggestion that is only a heuristic.
- Sign handling covers "same", "opposite" and "ignore". It cannot fix a file that mixes both conventions inside itself.
- XLSX support is first-sheet (or chosen sheet), values only. Dates stored as plain numbers without a date format are not recognised as dates. Hidden sheets are ignored.
- Not tested: real Excel-authored workbooks with merged cells, very wide sheets, tables with totals row, or a password-protected modern xlsx (those are detected only as "not a valid xlsx" or the old OLE container).
- Not tested on macOS. No Windows-specific code was used, but the Mac build has not been exercised.
- The model server is shared; 4B output can be loose. The guard (numbers, rows, JSON shape) makes bad output fall back to a labelled standard summary rather than reach the user as model text.
